# 새 노트의 시험문제 추가 자동화 계획

## 목적과 범위

앱에서 대상 노트와 프롬프트를 함께 복사하고, 외부 AI가 여러 JSON 파일을 하나로 묶어 만든 ZIP을 앱에 넣은 뒤 결과를 검토·적용한다.
AI API는 사용하지 않는다. 사용자는 현재 이용 중인 AI 채팅에 직접 자료를 전달한다.
수동으로 남는 작업은 앱의 프롬프트·데이터를 복사해 AI에 전달하고, AI가 만든 ZIP 파일을 앱에 드래그하는 과정이다.
Google Sheets에서 결과 파일을 가져오는 단계는 없다. 시트 추가는 앱이 자동 처리한다.
기존 문제 풀이·카테고리 선택·보기 섞기·Space 조작·원본 노트 열람은 유지한다.
기존 문제 수정·삭제 및 수정 노트의 재출제·교체는 1차 범위에서 제외한다.

## 진입과 세 단계 화면

앱 상단의 관리 영역에 문제 출제 버튼을 제공한다. 기존 카테고리 오른쪽 클릭은 저장된 문제 풀이로 유지한다.
문제 출제 버튼을 누르면 단계 표시가 있는 창을 연다.
창 상단에는 **1. 자료 만들기**, **2. 파일 넣기**, **3. 검토·적용** 버튼을 항상 표시하며 어느 단계든 직접 들어갈 수 있다. 기본 흐름은 1단계에서 자료 생성, 2단계에서 파일 입력, 3단계에서 결과 확인 순서다.

### STEP 1 — AI에게 전달할 자료 만들기

화면 순서는 다음과 같다.

1. 전체 노트 탭을 대상으로 한다는 안내
2. **미출제만 만들기**, **전체 새로 만들기** 버튼
3. 프롬프트와 데이터가 이어지는 하나의 복사 영역
4. “이걸 복사해서 AI에게 전달하세요.” 안내와 전체 복사 버튼
5. AI 결과 파일 입력 단계로 이동하는 다음 버튼

복사 영역에는 전체 프롬프트를 가장 먼저 배치하고, 그 뒤에 이번 출제 정보·미출제 노트·중복 참고용 기존 문제를 배치한다.
프롬프트와 데이터를 따로 복사할 필요가 없다. 생성 전에는 안내를 표시하고, 생성 후 대상 노트 수와 범위를 보여준다.
전체 복사 버튼은 화면에서 일부 내용만 보이더라도 생성된 전체 텍스트를 복사한다.
클립보드 사용이 실패하면 영역 전체 선택으로 직접 복사할 수 있게 한다.

두 버튼 모두 연결된 스프레드시트의 전체 노트 탭을 대상으로 하며 탭별 범위 선택은 제공하지 않는다.
미출제 노트 출제는 유효한 기존 문제와 현재 제외 기록이 없는 노트만 포함한다.
전체 새로 만들기는 기존 문제와 제외 기록에 관계없이 모든 유효한 노트를 포함하고 새 임시 문제은행 탭을 만든다. 2단계의 결과는 임시 탭에만 저장하며 운영 문제은행은 3단계 적용 전까지 유지한다.
앱에서 보고 있는 카테고리나 시트에서 선택해 둔 탭에 영향을 받지 않는다.
데이터 생성 시 서버에서 최신 노트와 문제은행을 읽으며, 앱에 이미 로드된 노트만으로 대상을 결정하지 않는다.
대상이 없으면 “미출제 노트가 없습니다”를 표시하고 빈 출제 묶음을 만들지 않는다.

### STEP 2 — AI 결과 파일 넣기

“AI가 만든 ZIP 파일을 넣으세요”라는 안내와 파일 드롭 영역을 제공한다.
사용자가 ZIP을 드래그하거나 파일 선택 창에서 고르면 내부 JSON을 이름 순서대로 풀고, 내부 검사 후 유효한 새 문제를 자동으로 시트에 추가한다.
JSON 텍스트 직접 입력은 파일을 받을 수 없는 AI를 위한 보조 경로로 유지한다.
압축하지 않은 개별 JSON 파일이나 여러 JSON 파일도 호환 경로로 계속 받는다.
별도의 검사 버튼·검사 승인·시트 복사 작업은 필요 없다.

- 파일 선택 또는 드롭 완료를 기준으로 처리하며 파일별 진행·완료·실패 상태를 표시한다.
- 저장 중에는 진행 상태를 표시하고 동일 입력의 중복 요청을 막는다.
- 파일 하나의 JSON 전체를 해석할 수 없으면 그 파일은 저장하지 않고 실패를 표시하며 나머지 파일은 계속 처리한다.
- 전체 JSON은 유효하나 일부 문항만 잘못되었다면 정상 문항은 추가하고 해당 문항만 보류한다.
- 직접 수정한 입력을 다시 처리할 수 있도록 다시 추가 버튼을 제공한다.
- 성공 후 “추가 20개 · 이미 추가됨 3개 · 보류 2개”와 보류 사유를 표시한다.
- 파일별 결과와 보류 내용을 화면에 유지해 수정한 파일만 다시 넣을 수 있게 한다.
- 저장 성공 후 앱의 문제은행을 새로 읽어 추가한 문제를 바로 풀 수 있게 한다.

파일 처리가 끝나면 3단계로 자동 이동한다. 일부 파일이 실패하거나 미처리 노트가 남으면 2단계로 돌아가 파일을 더 넣을 수 있다.

### STEP 3 — 검토·적용

대상 노트 수, 처리된 노트 수, 남은 노트 수와 파일별 추가·중복·제외·보류 결과를 표시한다. 서버의 현재 상태를 다시 읽는 버튼도 제공한다.

- 미출제만 만들기는 2단계에서 기존 `시험문제` 탭에 저장되므로 3단계에서 완료 결과를 확인한다.
- 전체 새로 만들기는 새 임시 탭에 저장한다. 모든 대상 노트가 문제 생성 또는 명시적 제외로 처리되어 남은 수가 0일 때만 **새 문제은행 적용** 버튼을 표시한다.
- 적용하면 기존 운영 탭을 `시험문제_이전_...` 이름으로 보관하고 임시 탭을 `시험문제`로 바꾼 뒤 운영 시트 ID를 새 탭으로 갱신한다.
- 처리되지 않은 노트가 하나라도 있으면 적용 요청을 서버에서도 거부한다.

단계를 오가도 생성 자료와 입력을 유지한다. 새 데이터 생성으로 기존 묶음을 바꾸는 경우 이를 명확히 표시한다.
이미 발급된 묶음의 결과는 해당 batch_id로 처리하여, 여러 AI 작업의 파일을 역순으로 넣어도 구분한다.
페이지를 다시 열어도 서버에 기록된 묶음은 유지한다. 복구되지 않은 입력을 저장 완료라고 표시하지 않는다.

## 노트 탭 범위와 미출제 판별

노트 탭은 첫 두 열이 category, text인 탭이다. 운영 문제은행·백업·이력 등 등록된 관리 탭은 먼저 제외한다.
전체 탭은 현재 연결된 스프레드시트의 모든 노트 탭이며 각 탭의 모든 데이터 행을 검토한다.
필터·숨김 여부와 관계없이 해당 범위를 사용하고, category 문자열은 원본대로 보존한다.
공무직 탭에 여러 카테고리가 있으면 그 탭에 있는 카테고리가 모두 대상이 된다.

- C열의 실제 노트 ID를 사용하며 화면 임시 ID는 사용하지 않는다.
- 기존 짧은 ID와 UUID는 문자열 그대로 유지한다.
- 빈 ID만 전체 노트 탭과 겹치지 않게 생성하여 원본에 저장한다.
- ID 중복 검사는 전체 노트 탭을 기준으로 한다.
- 중복된 기존 ID는 자동 재발급하지 않고 해당 노트를 보류하며 탭·행 위치를 안내한다.
- 기존 fillIds의 중복 ID 재발급 처리도 이 원칙에 맞게 보완한다.
- 유효한 운영 문제의 source_ids에 연결된 노트는 출제됨이다.
- 연결 문제도 없고 현재 본문에 적용되는 제외 기록도 없으면 미출제다.
- 기존 문제 데이터 오류로 연결 여부를 확정할 수 없으면 오류를 안내한다.

출제됨은 문제가 하나 이상 있다는 뜻이며, 모든 사실을 문제화했다는 뜻은 아니다.
원본 노트에 별도 상태 열을 강제로 추가하지 않는다.
현재 Quote.sheetId는 실제 노트 ID를 뜻하므로 실제 탭 ID와 혼용하지 않는다. 탭 정보는 별도 필드로 전달한다.

## 복사 자료와 프롬프트

하나의 텍스트에 다음 순서로 담는다.

| 순서 | 내용 |
|---|---|
| 1 | 전체 출제 프롬프트와 AI 답변 형식 |
| 2 | batch_id, 새 문제 ID 접두어, 전체 노트 탭 대상 안내 |
| 3 | 미출제 노트: id, category, text, source_sheet |
| 4 | 중복 참고용 기존 문제: id, category, source_ids, question, correct_answer |

데이터 부분은 JSON으로 직렬화하여 본문 줄바꿈·큰따옴표·역슬래시를 보존한다.
기존 문제는 전체 노트 탭의 노트와 연결된 것을 포함한다. 저장 시 ID 중복 검사는 운영 문제은행 전체에서 한다.
AI는 미출제 노트만 출제 근거로 사용하고, 기존 문제는 중복 확인용으로만 사용한다.
설정값·쓰기 키·범위 밖 노트·백업·처리 이력은 복사 자료에 포함하지 않는다.
자료 안의 지시문은 실행하지 않고 학습 내용으로만 취급하도록 프롬프트에 명시한다.

저장소의 기본 출제 프롬프트를 사용한다. 기존 출제안내 관리 탭에 사용자 프롬프트가 있다면 보존한다.
공통 출제 지침과 필수 응답 형식을 구분하여, 사용자 지침이 있어도 이번 묶음 ID와 JSON 계약을 포함한다.
기존 파일 출력 지침과 충돌하는 경우 데이터 생성 단계에서 안내하고, 서로 모순된 지시를 함께 내보내지 않는다.
자료를 조용히 잘라 내지 않는다. 처리 가능한 크기를 넘으면 생성 불가 사유를 표시하고 완료로 처리하지 않는다.
대용량 대응이 필요해도 사용자가 탭을 골라 누락시키는 방식 대신 전체 대상의 처리 범위를 추적하는 방식으로 보완한다.
Drive 임시 파일과 Google Sheets의 파일 가져오기 기능은 사용하지 않는다.

## AI 결과 파일 계약

AI에게 전체 결과를 UTF-8 JSON 파일 여러 개로 생성한 뒤 하나의 ZIP 파일로 묶도록 요청한다.
파일 하나에는 최대 12개 원본 노트의 결과만 담고 `발급접두어-part-001.json`부터 파일 번호를 올린다.
ZIP 파일명은 `발급접두어.zip`으로 하고 내부에는 결과 JSON만 넣는다.
모든 파일은 같은 batch_id를 사용하고 문제 ID는 파일 사이에서도 겹치지 않게 연속 번호를 사용한다.
각 파일은 순수 JSON 객체이며 마크다운 코드 블록이나 설명문을 파일 내용에 섞지 않는다.
보조 직접 입력 경로는 순수 JSON 또는 JSON을 감싼 단일 코드 블록을 받는다.

~~~json
{
  "batch_id": "발급된 묶음 ID",
  "questions": [
    {
      "id": "발급된접두어-0001",
      "category": "원본 카테고리",
      "source_ids": ["실제 노트 ID"],
      "question": "문제",
      "correct_answer": "정답",
      "distractors": ["오답 가", "오답 나", "오답 다", "오답 라"],
      "explanation": "근거 해설",
      "created": ""
    }
  ],
  "results": [
    {
      "source_id": "실제 노트 ID",
      "status": "generated",
      "reason": ""
    }
  ]
}
~~~

- questions는 새 문제만 담는다. 기존 문제를 다시 출력하거나 수정하지 않는다.
- 문제 ID는 발급한 접두어와 연속 번호를 사용한다.
- source_ids에는 해당 묶음의 실제 노트 ID만 사용한다. 복수 근거 노트의 카테고리는 같아야 한다.
- 오답은 6~8개를 목표로 하되 최소 4개를 요구한다. 앱은 정답과 임의의 오답 3개를 섞는다.
- 기존 출제 프롬프트의 근거 한정·단일 정답·독립적인 오답·간결한 해설 원칙을 유지한다.
- created는 확정 가능한 작성일 YYYY-MM-DD 또는 빈 문자열이다.
- results는 노트별 generated, excluded, unprocessed 중 하나다. excluded에는 사유가 필요하다.
- 미검토 또는 출력하지 못한 노트는 unprocessed로 표시한다.
- results 누락은 제외로 간주하지 않는다. 유효한 문항 자체는 추가할 수 있다.
- 출력 제한은 파일 수를 늘려 해결하며 분량 때문에 노트를 미처리로 표시하지 않는다.
- 잘린 JSON 파일은 저장하지 않는다. AI에게 해당 파일만 완결된 JSON으로 다시 만들도록 안내한다.

시트의 기존 8열은 유지한다.

~~~text
id | category | source_ids | question | correct_answer | distractors | explanation | created
~~~

앱·서버가 JSON 객체를 이 8열로 변환하고 배열은 JSON 문자열로 저장한다.
사용자가 탭 문자나 시트 열 순서를 직접 맞출 필요가 없다.

## 묶음 기록과 원본 변경

서버의 관리 이력에 batch_id, 대상 노트 ID, 실제 원본 탭 ID, 카테고리와 본문 해시를 저장한다.
묶음별로 기록하여 다음 자료 생성이 이전 기록을 덮어쓰지 않는다.
클라이언트가 보내온 원본 정보만 신뢰하지 않고 서버 기록 및 현재 시트와 대조한다.
알 수 없는 batch_id는 저장하지 않으며 데이터 생성부터 다시 진행하도록 안내한다.

파일을 처리할 때 원본 수정·삭제·ID 모호성이 발견되면 해당 문제와 제외 기록을 보류한다.
본문 해시로 비교하여 시트에서 직접 수정한 경우도 감지한다.
변경된 미출제 노트는 다음 생성에 다시 포함하며, 이미 문제가 있는 노트의 자동 재출제는 제외한다.

## 내부 검사와 중복 처리

응답 전체의 JSON 구조·batch_id 확인 후 문항별로 검사한다.

- 필수 필드와 문자열 배열 형식
- 이번 묶음의 실제 노트 ID 및 현재 원본 일치
- 문제와 근거 노트의 카테고리 일치
- 문자열 기준 서로 다른 오답 최소 4개 및 정답과의 중복
- 셀 내 탭·줄바꿈, 날짜 형식
- 응답 내부 및 운영 문제은행 전체의 문제 ID 충돌

정답 사실성이나 의미상 중복까지 자동으로 검증했다고 표시하지 않는다.

| 결과 | 처리 |
|---|---|
| 유효한 새 ID | 운영 문제은행 끝에 추가 |
| 기존 ID·같은 내용 | 이미 추가됨으로 건너뜀 |
| 기존 ID·다른 내용 | 보류하고 기존 행 유지 |
| 응답 내부 같은 ID·같은 내용 | 한 번만 처리 |
| 응답 내부 같은 ID·다른 내용 | 해당 ID의 모든 후보 보류 |
| 잘못된 형식·출처·변경된 원본 | 해당 문항 보류 |

동일성은 정의된 날짜·JSON 정규화 후 8개 필드를 비교하며 문장의 의미를 바꾸지 않는다.
같은 파일을 다시 넣거나 응답 유실 후 재시도해도 이중 추가되지 않아야 한다.
한 노트의 문제 일부만 성공한 경우 같은 묶음의 나머지 문항을 수정해 추가할 수 있다.
그 노트가 출제됨으로 바뀌었다는 이유만으로 같은 묶음의 나머지 문제를 차단하지 않는다.

## 저장 경로와 운영 문제은행

앱의 자료 생성·결과 추가 요청은 서버 경유로 Apps Script에 전달한다.
기존 쓰기 인증 방식을 적용하고 데이터 생성에 따른 ID·묶음 기록도 인증된 경로에서 수행한다.
쓰기 키를 브라우저나 AI 복사 자료에 노출하지 않는다.
서버에서도 입력을 재검사하고 크기 제한을 두며, AI 답변을 실행할 코드나 시트 수식으로 취급하지 않는다.

현재 quizSheet는 8개 머리글이 일치하는 첫 탭을 선택한다.
운영 탭을 실제 시트 ID로 등록하고 읽기·추가·카테고리 변경에서 공통 사용하도록 보완한다.
최초 후보가 하나면 등록하고, 여러 개면 운영 탭을 한 번 선택하게 한다.
등록 탭이 삭제되거나 형식이 잘못되면 오류를 표시하며 임의의 다른 탭으로 대체하지 않는다.
백업·이력·제외 등 관리 탭은 운영 문제은행과 노트 탐색에서 제외한다.

## 보존과 실패 복구

검사·저장 시 잠금 안에서 최신 문제 ID와 원본을 다시 확인한다.
실제 추가 직전에 운영 탭을 백업하며 백업 실패 시 추가하지 않는다. 백업 자동 삭제는 이번 범위에 없다.
유효 문항을 모아 끝에 추가하고 기존 문제 행은 덮어쓰거나 삭제하지 않는다.
문자열을 수식으로 실행하지 않는 쓰기 방식으로 저장하고 실제 셀 값과 수식 여부를 확인한다.

여러 탭 쓰기를 하나의 트랜잭션으로 가정하지 않는다.
문제 저장 후 이력 기록이 실패하면 실제 문제 ID·내용을 기준으로 재시도를 복구한다.
반영 여부가 불명확한 통신 실패를 무조건 미반영으로 표시하지 않는다.
입력을 유지하고 재시도 시 서버에서 실제 저장 상태를 확인한다.

## 제외와 미처리

별도 출제제외 관리 탭에 source_id, reason, source_hash, batch_id, excluded_at, active를 저장한다.

- 명시적인 제외 사유와 일치하는 원본이 있을 때만 제외를 반영한다.
- 미처리·결과 누락·검사 실패는 제외로 기록하지 않는다.
- 같은 노트에 문제와 제외가 함께 반환되면 제외 기록은 보류하고 문제를 독립 검사한다.
- active를 해제하면 다시 출제 대상으로 삼을 수 있다.
- 본문·카테고리 변경 시 이전 해시의 제외는 적용하지 않는다.
- 제외 기록은 원본 노트나 기존 문제를 삭제하지 않는다.

## 구현 순서와 완료 기준

1. 운영 문제은행 식별과 전체 노트 ID 처리 보완
2. 인증된 전체 노트 탭 자료 생성·묶음 기록 경로 구현
3. 앱의 문제 출제 버튼과 STEP 1 데이터 생성·전체 복사 화면 구현
4. JSON 응답 계약에 맞춘 기본 프롬프트 갱신
5. STEP 2 다중 파일 드롭 자동 추가·보류 안내·재시도 구현
6. STEP 3 처리 현황 확인과 전체 재출제 문제은행 교체 구현
7. 제외 기록·원본 변경·백업·실패 복구와 문제은행 새로고침 연결

사용자가 앱 → AI 채팅 → 앱의 세 단계 흐름으로 새 문제를 저장하고 전체 재출제 결과를 안전하게 적용할 수 있어야 완료다.
Google Sheets를 직접 열어 복사·가져오기·추가 메뉴를 실행할 필요가 없어야 한다.
이전 문제은행과 사용하지 않는 임시 탭의 자동 정리는 후속 범위다.

## 검증 시나리오

- 항상 전체 노트 탭을 대상으로 하는지 확인, 관리 탭 제외와 실제 탭 ID·노트 ID 구분
- 프롬프트가 먼저 나오고 전체 데이터가 한 번에 복사됨
- 빈 대상·복사 실패·분량 초과 시 정확한 안내
- 짧은 ID·UUID·빈 ID·탭 간 중복 ID와 기존 원본 연결 보존
- STEP 이동 후 자료·입력 유지, 여러 묶음 결과의 역순 처리
- 순수 JSON·코드 블록·잘린 응답·잘못된 배열·알 수 없는 묶음
- ZIP 파일 드롭, 내부 JSON 자동 압축 해제·순차 저장과 수정한 개별 파일 다시 추가
- 전체 재출제 임시 탭 저장, 미완료 적용 차단, 완료 후 운영 탭 교체와 이전 탭 보관
- 같은 답변 반복·부분 성공 후 재시도·응답 내부 ID 충돌
- 원본 수정·삭제·카테고리 변경 및 제외·미처리 구분
- 인증 실패·통신 실패·이력 실패·백업 실패 후 저장 상태 확인
- 한글·큰따옴표·역슬래시·긴 본문·수식 시작 문자열 보존
- 기존 문제 풀이·Space 조작·원본 보기·카테고리 변경 정상 동작
